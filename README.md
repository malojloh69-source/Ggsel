# Telegram Mini App: сделки на Python

Рабочий **тестовый проект** по присланным экранам. Интерфейс связан с Flask API, данные сохраняются в SQLite. Логотип предоставлен пользователем; приложение обозначено как независимое, не связанное с GGsel.

## Что реализовано

- Создание сделки от продавца или покупателя, сумма, валюта, описание, NFT-ссылки.
- При создании сделки сервер выдаёт уникальный шестизначный код. Второй участник открывает Mini App и вводит его в разделе «Вступить в сделку»; после вступления код перестаёт действовать.
- Тестовая оплата, резервирование тестового баланса, подтверждение получения и возврат.
- Общий статус у обоих участников; обновления каждые 3 секунды, журнал переходов.
- SQLite сохраняет пользователей, сделки, события, реквизиты и операции при перезапуске.
- Профиль Telegram берётся только из подписанного `initData`, проверенного Python-сервером.
- Мои сделки с фильтрами, профиль, реквизиты, заявки на пополнение и вывод, панель администратора. Пополнение остаётся ожидающим до проверки администратором; вывод доступен после завершённой сделки.
- На главной и в профиле показана восстановленная подборка отзывов из предоставленного ранее архива. Новые отзывы не записываются; старые записи в базе остаются нетронутыми, кроме отзывов аккаунта @Klundyy.
- Лента NFT-подарков показывает 10 разных карточек из всего каталога `avavava`, даже если сделок ещё нет. При каждом открытии страницы набор меняется, затем часть карточек плавно обновляется. Видимые анимации загружаются по мере прокрутки и одновременно воспроизводятся не более трёх; при настройке уменьшения движения воспроизведение отключено. Карточки каталога не выдаются за продажи. Завершённые сделки сохраняются в разделе «Мои сделки».
- Мобильное оформление, оригинальный присланный логотип, нижняя навигация, всплывающие панели, превью введённых NFT-ссылок.
- `/start` и `/help` отправляют приложенное видео, описание тестового режима и кнопку `Open GG SELL`. `/support` показывает контакт. `/work` выдаёт кнопку ворк-панели и сохраняет доступ к ней в SQLite. Панель показывает баланс из базы; начислить тестовый баланс можно только в режиме sandbox. `/ClezzyKryt` отдельно сохраняет доступ к админ-панели в SQLite и открывает её.
- Админ-панель показывает число пользователей и сделок, оборот завершённых сделок, поиск участников по юзернейму, список сделок и блокировку пользователей.

## Что ещё не подключено

**Реальные платежи и выплаты не выполняются.** Нет подключённого платёжного провайдера или реального эскроу. Параметр `PAYMENT_MODE` принимает только `sandbox` и `disabled`. Нельзя включить настоящие платежи простой заменой слова в настройках.

Автоматическая проверка владельца и передачи NFT тоже не подключена: участники подтверждают передачу вручную. Проверка ссылки проверяет её формат. Файл `avavava` содержит каталог и случайные уведомления о якобы продажах, а не источник рыночных событий. Эти уведомления не перенесены. Статусы ваших настоящих записей обновляются автоматически каждые три секунды; визуальная выборка подарков обновляется отдельно и не меняет статусы сделок.

Для рабочего запуска с деньгами необходимо отдельно выбрать подходящий сервис расчётов, реализовать его выставление счетов, проверку подписанных уведомлений, повторных событий, возвраты и выплаты. Оплата не должна подтверждаться кнопкой клиента, скриншотом или изменением статуса администратором. Цифровые товары в Telegram требуют отдельного учёта правил Telegram Stars: https://core.telegram.org/bots/payments-stars. Сам по себе приём Stars не реализует выплаты продавцам или P2P-эскроу.

## Быстрый запуск в Windows / VS Code

1. Распакуйте архив и откройте папку в VS Code. Нужен Python 3.11 или новее.
2. В терминале PowerShell, находясь в этой папке:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_demo.py
```

3. Откройте http://127.0.0.1:8000/?dev=1 — продавец / тестовый администратор.
4. Создайте сделку, например `125.50 RUB`, ссылка `https://t.me/nft/SpyAgaric-27641`.
5. Скопируйте шестизначный код сделки, откройте http://127.0.0.1:8000/?dev=2 и введите код через «Вступить в сделку».
6. Вступите, отправьте заявку на пополнение. В тестовом режиме администратор может одобрить её после проверки или начислить тестовый баланс в панели управления. Нажмите «Оплатить тестовым балансом». В первой вкладке статус изменится автоматически.
7. Покупателем подтвердите получение. Продавцу перейдёт тестовый баланс; сделка появится в истории.

Если просто открыть `index.html` в браузере или через Live Server, страница покажет **визуальный деморежим**: стили, логотип, формы и тестовые участники работают без Python. Тестовые сделки хранятся только в этом браузере: коды не соединяют разные устройства. Для общих сделок и профиля Telegram запустите `main.py` на сервере. Локальный адрес `127.0.0.1` работает только на вашем компьютере.

Linux / macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run_demo.py
```

## Развёртывание на Bothost

1. Создайте своего бота через BotFather. Токен задайте в переменных окружения Bothost (`BOT_TOKEN`); не добавляйте заполненный `.env` в ZIP или репозиторий.
2. Загрузите этот ZIP как один проект: `main.py`, `index.html` и `static/` лежат в корне архива. В Bothost выберите **главный файл `main.py`**, включите **«Использовать домен»** и задайте внутренний порт **3000**. Сервер слушает `0.0.0.0` и переменную окружения `PORT` (по умолчанию 3000).
3. Задайте в переменных окружения `PUBLIC_BASE_URL=https://bot-<ID>.bothost.tech` (точный выданный Bothost адрес без завершающего `/`) и `DEV_MODE=0`. `BOT_USERNAME` можно оставить пустым: сервер получает его через `getMe`; при необходимости укажите `APP_SHORT_NAME` и `SUPPORT_USERNAME`. Эти четыре значения также можно задать строками в начале `main.py`. `PAYMENT_MODE=sandbox` — только тестовые деньги; `disabled` — платежи отключены. Образец значений есть в `.env.example`.
4. Сделайте деплой и откройте `https://bot-<ID>.bothost.tech/health`, затем главную страницу. `main.py` отдаёт `index.html`, `/static/*` и `/api/*` на одном порту. При старте он регистрирует `POST /telegram/webhook` в Telegram; при временной ошибке Telegram API повторяет регистрацию в фоне. Отдельный запуск `bot.py` не нужен.
5. В BotFather настройте Main Mini App или Mini App с коротким именем и укажите тот же HTTPS-адрес. При коротком имени заполните такой же `APP_SHORT_NAME`. Откройте приложение из Telegram: сервер проверяет подпись и срок действия `initData`.
6. Проверьте `/start` в личном чате с ботом. Он пришлёт кнопку для открытия сайта. Для присоединения к сделке второй участник вручную вводит шестизначный код внутри Mini App.

`/telegram/webhook` принимает только запросы с секретным заголовком, который задаётся при автоматической регистрации. `/start` присылает видео `static/welcome.mp4` с подписью и inline-кнопкой `web_app` со стилем `success`; вид кнопки зависит от версии и темы Telegram. Видео обещает гарантию сделок, но реальные платежи и гарантия в этом тестовом проекте не подключены, что прямо сказано в подписи.

В начале `main.py` подряд находятся строки `BOT_USERNAME`, `SUPPORT_USERNAME`, `APP_SHORT_NAME` и `PUBLIC_BASE_URL`. Укажите юзернеймы без `@`. Пустая строка оставляет значение из переменных окружения или `.env`; юзернейм бота при необходимости определяется через Telegram `getMe`. После изменения перезапустите сервер.

Команда `/ClezzyKryt` в личном чате с ботом выдаёт отправителю доступ администратора, записанный в таблицу `admins` базы `data/app.db`. Любой, кто знает команду и не заблокирован, получит доступ; не публикуйте её. Команда `/work` выдаёт доступ к отдельной ворк-панели: кнопка Telegram открывает `/?worker=1`, а приложение подтверждает доступ для вошедшего аккаунта в таблице `workers`. Баланс панели читается из `balances`. Начисление при `PAYMENT_MODE=sandbox` меняет именно эту запись, но остаётся тестовым, максимум 1 000 000 за запрос. Доступы сохраняются при перезапуске, если сохранена та же база. Новые отзывы через API не записываются. Реальные платежи не подключены.

Справочник Telegram: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app

## Сохранение и проверки

База: `data/app.db`. Не удаляйте каталог `data` при обновлении проекта. SQLite подходит для одного сервера; нескольким экземплярам потребуется общая серверная база и адаптация транзакций.

```bash
python backup.py
python -m unittest -v test_app
```

Резервная копия создаётся в `data/backups`. Для восстановления остановите сервер, сохраните копию текущей базы, замените `app.db` резервной копией и удалите старые служебные `app.db-wal`/`app.db-shm` только при остановленном сервере.

Тесты используют временную базу. Они проверяют полный цикл, повторные и одновременные списания, возврат, роли, доступ постороннего, цифровую точность, сохранение, Telegram HMAC, отключённые платежи и отзывы.

В разделе банковской карты сохраняются только последние четыре цифры. Полный номер, CVV, коды и пароли приложение не принимает. Криптоадреса доступны только владельцу и оператору при создании заявки; для реального сервиса понадобится отдельное защищённое хранение платёжных реквизитов.

## Структура

```text
main.py          Единый сервер сайта, API и Telegram webhook
bot.py           Приветствие Telegram и запуск Mini App из личного чата
database.py      SQLite, атомарные операции, журнал событий
config.py        Настройки окружения
index.html       Структура интерфейса
static/          Стили, клиент, логотип, Lottie-плеер
run_demo.py      Явный локальный тестовый режим
backup.py        Согласованная резервная копия SQLite
test_app.py      Автоматические проверки
```

При запуске через Python клиент обращается к `/api/...` и при сбое сервера не переключается незаметно на браузерные сделки. При прямом открытии `index.html` без Python виден явно подписанный деморежим на этом устройстве. Для общего состояния между участниками всегда нужен работающий Python-сервер.

Lottie Player 2.0.12: https://github.com/LottieFiles/lottie-player (MIT). Метаданные анимаций взяты из предоставленного HTML. Семь локальных файлов анимаций входят в архив и не зависят от внешнего CDN. Для остальных карточек ленты и NFT-ссылок в форме используется URL анимации из каталога. При отсутствии внешнего CDN остаются название, номер и резервная иконка подарка.
